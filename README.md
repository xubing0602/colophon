# Colophon

**English** · [简体中文](README.zh-CN.md)

*A colophon is the printer's mark at the end of a book — a small emblem, and a note saying where and when the thing was made.*

An agent skill for Codex and Claude Code that turns each of your photographs into a square keepsake: the photograph exactly as you took it, joined to a panel of warm paper carrying a small hand-pressed seal of what is in the picture and a typed caption with the place and date. The aim is a piece that feels inked, typed and pressed by hand, not generated by AI.

## What it does well

**One square format, whatever you shoot.** Portrait, landscape, near-square or panorama, every result is a 2048×2048 square. A landscape photo gets its paper below; a portrait photo gets it on the right. The side is decided from the real image dimensions after EXIF rotation, so an iPhone photo stored sideways is never misread.

<p align="center">
  <img src="docs/examples/any-shape-to-square.webp" width="70%" alt="A landscape photo of Wadi Rum and a portrait photo of the Royal Exchange, each becoming the same square composite">
</p>

**The photograph is never redrawn.** Asking an image model to render the whole composite fails about half the time: canvases that are not square, cropped photos, paper on the wrong side. So the model draws only the seal, and a script does the layout, copying your photo's pixels at their true aspect ratio. Cropping and distortion cannot happen, and the skill runs `verify.py` on every output — square, paper on the correct side, photo region matching the original — before handing it over.

**It feels hand-made, not AI-made.** An image model draws the seal, but nothing should look generated. What gives a generated image away is evenness: even detail, even wear, even spacing, tidy symmetry. So the seal is drawn as ink pressed onto paper — fine grain, broken edges, uneven pressure, crisp in some passages and starved in others — in the photograph's own measured colours rather than a stock palette. The caption is typed, with a ribbon that strikes unevenly from letter to letter, and the paper carries its own grain and tone. How heavily each seal is pressed varies from photo to photo, the way a drawer of real stamped papers holds crisp impressions and faint ones side by side.

<p align="center">
  <img src="docs/examples/detail-seal-caption.webp" width="70%" alt="Close-up of the Wadi Rum seal in grainy terracotta ink beside a typed three-line caption">
</p>

**The right amount of randomness, and reproducible.** A batch where every caption sits in the same place in the same face reads as a template. So each photo gets its own look, sampled within ranges that all stay inside the house style: caption typeface and weight, how worn the typewriter ribbon is, where the seal and caption sit, seal size, paper tone and grain. The seed comes from the filename, so neighbouring photos differ, yet re-running one photo gives the identical result — a revision changes only what you asked it to. One flag, `--variation`, turns the variety up, down or off.

**Captions that are spelled right.** Place names and dates are typed by the script as real text at full resolution, never drawn by the image model, so they come out correct and sharp.

**Revisions are free.** Smaller seal, paper less aged, caption lighter, group moved to a corner: each is a flag, re-applied in a second without touching the photograph or generating anything new. Only a change to the seal's artwork needs a new image.

**Batches by row number.** Point it at rows of a CSV of places and dates, and it resolves filenames, captions and output names mechanically, so the wrong ten photos are never processed.

**Captions drafted from the photos.** No spreadsheet yet? It reads each photo's capture date and GPS position, looks up the city, region and country on OpenStreetMap, and writes a draft CSV. Correct it, add the place names only you know, or use it as it is.

## Quick start

```bash
git clone https://github.com/xubing0602/colophon.git
pip install -r colophon/scripts/requirements.txt

# Codex
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills" && cp -R colophon "${CODEX_HOME:-$HOME/.codex}/skills/colophon"
# Claude Code
mkdir -p ~/.claude/skills && ln -s "$PWD/colophon" ~/.claude/skills/colophon
```

Put your photos in `source/` and, optionally, a `manifest/metadata.csv` with place and date per file. Without one, the agent drafts it from the photos' EXIF and shows it to you before anything is made. Then ask your agent:

```
Use colophon on the photos in source/.
```

```
用 colophon 处理 metadata.csv 第 112 到 121 行的图片。
```

### Which agent

- **Codex** draws the seals itself. Nothing else to set up.
- **Claude Code** cannot generate images on its own. Everything except drawing the seal is plain Python and runs the same, so you have three ways to fill that one step:
  - **Give it an OpenAI API key.** Copy `.env.example` to `.env` and paste the key; Claude then draws each seal with `scripts/generate_seal.py`, which calls OpenAI's image API (a few US cents per seal). This script is new and has not yet been run against the live API; please open an issue if it misbehaves.
  - **Connect an image-generation MCP server** to Claude Code. Then it works as in Codex.
  - **Draw the seals yourself.** Claude writes one finished prompt per photo to `seals/prompts/`. Paste each into ChatGPT, Codex or any image tool, save the result as `seals/<photo>_seal.png`, and Claude composes and verifies the batch.

The scripts need Pillow, numpy, and pillow-heif for iPhone `.heic` files.

The rest of this page is the full manual: installation for each agent, every step run by hand, every option.

This repository *is* the skill: `SKILL.md` sits at its top level. Installing means
copying the whole directory into your agent's skills folder.

**The destination directory must be named `colophon`.** That name is how the
agent identifies and invokes the skill, and it has to match the `name:` in

### Notes

The skill calls no agent-specific tool. Where it says to generate the seal image,
the agent uses whatever image generation it has — that step is described in plain
language, not as a particular tool call. Codex has image generation built in.
Claude Code does not: give it an OpenAI API key for `generate_seal.py`, connect
an image-generation MCP server, or let Claude write the prompts to
`seals/prompts/` and generate the seals yourself (see
[Which agent](#which-agent)). Everything else is the Python in `scripts/`, which
runs the same anywhere.

`agents/openai.yaml` carries the Codex display name (钤记), the one-line
description, and the default prompt. Other agents ignore it.

## Step by step

The walkthrough below is the full manual loop. Every command and every block of
output is real. If you are driving this through an agent instead, skip to
[Using it with an agent](#using-it-with-an-agent) — the agent runs these same
steps for you.

All commands assume you are inside the skill's `scripts/` directory.

### Step 1 — Set up the folders

```
myproject/
  source/              the original photographs, untouched
  seals/               generated seal artwork, one per photo
  output/              finished composites
  manifest/
    metadata.csv       captions, one row per photo
```

These are the names the skill assumes, so using them means never having to say
where anything is. Keep `source/` pristine — the verifier compares finished work
back against it.

The CSV needs a column naming the file, plus whatever the caption draws on:

```csv
file_name,place,city,state,country,lat,lng,year,month,month_name,day
IMG_4705.heic,Chaoyang Road,Beijing,Beijing,China,...,2026,3,MAR,19
```

Only `file_name`, `place`, `city`, `country`, `month_name`, and `year` are used
by default. Extra columns are ignored.

No CSV yet? Draft one from the photos themselves:

```bash
python update_metadata.py --root /path/to/myproject
```

```
[1/3] 0m01s elapsed, ETA 0m03s  IMG_0113.heic  (new)  Kyoto, Japan / MAR 2023
[2/3] 0m05s elapsed, ETA 0m02s  IMG_0239.HEIC  (new)  Beijing, China / APR 2022
[3/3] 0m09s elapsed, ETA 0m00s  IMG_0322.heic  (new)  Kyoto, Japan / MAR 2023
done in 0m09s: 3 new row(s), 0 filled in, in /path/to/myproject/manifest/metadata.csv
3 row(s) have no place; fill them in, or the caption starts at the city
```

It reads the capture date and GPS from each photo's EXIF, and looks the position
up on OpenStreetMap (Nominatim) for city, state and country. Then open the CSV
and make it yours. A few things to know:

- **It only fills empty cells.** Anything already in the CSV is kept, rows keep
  their order so batch row numbers stay valid, and new photos are appended. Run
  it again after adding photos.
- **`place` stays empty** unless you pass `--suggest-place`. What to call a spot
  is your call, not a geocoder's; the suggestion (a building, park or street
  name from OpenStreetMap) is a starting point to edit.
- **Geocoding sends each photo's coordinates to OpenStreetMap**, one request a
  second. `--no-geocode` keeps everything on your machine and fills only the
  date and coordinates.
- Photos without a date or GPS are listed at the end, so you know which rows to
  fill by hand. `--dry-run` shows what would change without writing.

You do not have to act on any of this by hand. It is here so you know what to
expect, and so that on the fallback path you can paste real numbers into a
prompt instead of a conditional.

### Step 2b — Resolve the batch

If your captions live in a CSV, let a script turn row numbers into exact
commands rather than reading rows by eye:

```bash
python plan_batch.py --csv ../manifest/metadata.csv --rows 112-121
```

```
# 10 photo(s) from ../manifest/metadata.csv
# seals expected at seals/<stem>_seal.png

python compose.py --photo source/IMG_4705.heic --seal seals/IMG_4705_seal.png --caption 'Chaoyang Road' --caption 'Beijing, China' --caption 'MAR 2026' --out output/IMG_4705.webp
python compose.py --photo source/IMG_4738.heic --seal seals/IMG_4738_seal.png --caption Piccadilly --caption 'London, United Kingdom' --caption 'APR 2023' --out output/IMG_4738.webp
...
```

Row numbers are **data rows, 1-indexed, header excluded** — row 112 is line 113
of the file. This is the single easiest thing to get wrong by hand, and it fails
silently by processing the wrong ten photographs.

`--check` confirms every source exists before you spend any generation; `--json`
gives a machine-readable plan; `--files IMG_4705.heic,IMG_6773.heic` selects by
name instead of row. Captions, output basenames, and extensions all come out
mechanically correct.

### Step 3 — Generate one seal per photo

The one thing to hold onto: **the seal is a stamp inked and pressed onto paper**,
not a print of the photograph. 钤印 — the mark affixed at the end of a page. It is
small, fine-grained and quiet, and it sits beside the photograph without
competing with it.

Look at the photograph, then make two decisions.

**First, what the seal is about.** A seal is not obliged to carry the whole frame.

- *Whole view* — the composition the camera saw, its depth and flanking elements.
  Right when the composition is the subject: a tower at the end of an avenue is a
  picture of the avenue too.
- *Subject focus* — the primary subject alone, its surroundings reduced to a
  single loose stroke or dropped entirely. Right when one thing dominates: a
  sculpture, a pumpkin, a blossoming branch.

Both are correct. Choosing is the work, and saying which one you chose in the
prompt is what stops the model from defaulting to a shrunken copy of the frame.
Omitting a background is allowed; inventing one is not.

**Second, the shape** — from the subject, not from habit:

| Subject | Shape |
|---|---|
| compact rounded subjects, faces, icons, ceremonial motifs | circle or oval |
| signage, dense architecture, storefronts | square frame |
| rows, processions, coastlines, wide landscapes | panoramic ridge |
| windows, doors, portals, vaulted subjects | arch |
| distinctive buildings, vehicles, trees, statues, objects | irregular silhouette |
| a single dominant subject, surroundings dropped | no boundary at all |

The shape is only the seal's outer boundary, and several of the best seals have
none — just the inked subject sitting on the paper. It does not dictate how much
of the scene goes inside: an arched or circular seal can still hold the full
view, its flanking buildings and its sky.

Then let `build_prompt.py` write the prompt. It measures the palette itself and
emits every invariant clause verbatim, so you supply only the judgments:

```bash
python build_prompt.py --photo ../source/IMG_9001.heic \
  --subject "a mound of shaved ice with mandarin segments on a metal plate" \
  --focus subject --keep "the metal plate and the spoon lying on it" \
  --drop "the wooden table and its shadow" \
  --detail "the shaved-ice texture, the segments, the banana slices" \
  --lead-ink "the warm orange of the syrup" --support "a cool grey for the plate"
```

Treat the output as a draft to extend, not a prompt to send. It guards the floor —
a dropped clause is what turns a seal into a poster, and real hex values are facts
where "preserve the colour memory" is a wish a model will quietly swap a stock
palette in for. But it cannot raise the ceiling. Whatever you noticed in the
photograph that the flags cannot say — the way the stem leans, that the dots crowd
at the ribs and thin across the faces — write that in. It is usually the
difference between a competent seal and a good one.

Note `--keep`: subject focus is not cutting the subject out. What physically
carries or contains it comes along — the plate under the dessert, the pier under
the pumpkin, the branch the blossoms are on. The wider environment is what goes.

The full template, the whole negative list, and the reasoning behind each clause
are in [`reference/seal-prompt.md`](reference/seal-prompt.md); write a prompt by
hand only when a photograph needs something the flags cannot say.

What it emits, for a yellow polka-dot pumpkin standing on a concrete pier, looks
like this:

```text
Asset type: one small hand-pressed seal impression, inked and affixed to paper --
the character of a rubber stamp or a Japanese hanko pressed by hand. Alone on
blank paper.

Subject: a large yellow pumpkin covered in black dots, standing on a concrete
pier by the sea.

FOCUS. Center on the pumpkin. Reduce the surroundings to a light suggestion --
one loose horizontal stroke of pale blue behind and beside it for the sea -- and
leave out the pier, the hills and the sky.

INK CHARACTER. Fine, granular and delicate. The impression is built from small
ink grain, stipple and softly broken edges -- ink sitting on absorbent paper,
with the pressure uneven and the edges eaten slightly. Detail survives and is
wanted: every dot on the pumpkin, its ribbed segments, the curl of the stem. It
survives as fine ink marks and grain, never as smooth photographic tone.

NOT a bold graphic reduction. No large flat fields of solid colour, no heavy
linocut slabs, no thick graphic outlines, no poster-style simplification.

NOT a processed photograph. Do not threshold, halftone-screen, dither, posterise,
duotone, trace or auto-vectorise the photograph.

DERIVED, NOT DESIGNED. The dots are the size and spacing they actually are, dense
at the ribs and sparser across the faces. The stem leans the way it leans. Do not
tidy or regularise them.

Shape: no boundary -- the inked pumpkin alone on the paper.

Colour: take every ink from the photograph itself. Its measured palette is: mid
moderately saturated yellow #d9b83c (18% of the frame); very dark neutral grey
#1c2029 (14%); light muted blue #a8c4d8 (31%); mid muted blue #6d94b4 (22%). Keep
each element at its real hue and lightness. The yellow leads at its real strength
-- this pumpkin is vividly yellow and the seal should be too -- with the
near-black dots and one pale blue stroke subordinate to it in coverage. Do not
deepen or saturate a colour to make the print look bolder, and do not wash the
yellow out to make it look restrained.

Scale and weight: small, light and quiet on the page — delicate rather than
emphatic, closer to a botanical stamp or a library mark than to a poster.

Surround: outside the seal's own edge, plain near-white empty paper, with a
generous clean margin on all four sides. Nothing besides the single impression.

Output: a single seal, centred, filling roughly two thirds of the frame.

Do not include: any caption, lettering, date, place name, or number that is not
physically part of the subject; any border or frame around the whole image; drop
shadows; paper texture; torn edges; a mockup; multiple stamps; a sticker, badge,
crest, shield, emblem, logo, roundel, medallion, banner, ribbon, or travel-label
look; symmetrical, evenly spaced, tidied or idealised arrangement; generic stock
elements standing in for what the photograph shows; invented content; recoloured
or stock-palette inks; bold poster reduction; large flat colour fields; heavy
linocut slabs; thick graphic outlines; glossy finish; clean vector flatness;
smooth gradients or blends; continuous photographic tone; repeated worm-like
squiggles; maze patterns; moiré; fingerprint-like loops; ornamental curls; tiled
or uniform noise fill.
```

Five requirements do real work downstream, so do not drop them:

- **Inked and pressed, delicate not emphatic.** This is the axis that is easiest
  to lose and hardest to notice in isolation. Asking for "a print in limited inks"
  pulls hard toward a linocut poster — big flat shapes, thick outlines, three
  saturated colours — which looks competent alone and overwhelms the photograph
  it sits beside. Say *pressed onto paper*; never say "cut coarse", "flat inks",
  or "carved block". Detail is not the enemy here — smooth tone is. Petals,
  dots and mouldings should all be there, arriving as ink grain rather than as
  photographic gradient.
- **Colour follows the photograph, in both directions.** Paste the Palette line
  in and keep each element at its real hue and lightness. Vivid stays vivid: a
  seal may be genuinely colourful, and what keeps it quiet is its small size and
  light ink weight, not a drained palette. Draining a strong colour in the name
  of restraint is the same error as inventing one — it just fails quietly instead
  of loudly. `check_seal.py` flags both directions.
- **Near-white empty background.** The compositor multiplies the seal into the
  real paper and knocks out the seal's own ground. A dark or busy ground survives
  that as a visible rectangle.
- **No caption or lettering.** The caption is rendered as real typewriter text at
  full resolution, so it is spelled correctly and stays sharp. Text drawn by an
  image model is neither.
- **No border around the whole image.** A square *seal* border is wanted. A border
  around the whole generated frame becomes a stray box sitting on the paper.

Save each result as `seals/<photo-stem>_seal.png`. PNG, not JPEG — JPEG ringing
around the ink fights the knockout.

One thing you do **not** have to get out of the model: perfectly uneven pressure.
`compose.py` presses the seal unevenly itself, at the size it is finally printed —
starving the ink in some passages so strokes break into specks and skips, leaving
others crisp. Ask the prompt for fine grain and eaten edges; the regional
unevenness is added on top, and `--seal-wear` dials it. Fine specks only survive
if they are made at final size, which is why this is the script's job rather than
the model's.

### Step 3b — Check the seal's colours before spending a composite

```bash
python check_seal.py --photo ../source/IMG_4705.heic --seal ../seals/IMG_4705_seal.png
```

It compares the seal's inks against the photograph's measured palette and flags
substituted stock colours, punched-up saturation, washed-out colour, and
lightness drift — the
failure that is genuinely hard to see by eye, because a bolder palette looks
*better* until you set it next to the source. It is advisory, not a gate: it tells
you where to look and your eyes decide. A flagged seal is usually worth resealing
with the Palette line pasted in rather than accepting.

### Step 4 — Composite

```bash
python compose.py \
  --photo /path/to/myproject/source/IMG_1588.heic \
  --seal  /path/to/myproject/seals/IMG_1588_seal.png \
  --caption "Teshima Art Museum" \
  --caption "Kagawa, Japan" \
  --caption "OCT 2019" \
  --out   /path/to/myproject/output/IMG_1588.webp
```

```
/tmp/demo/output/IMG_1588.webp  2048x2048  landscape -> paper bottom  (bleed)  seed 194563074  stacked/right
```

The confirmation line tells you the canvas size, the orientation it detected,
which side the paper went on, whether the photo bled to the edges or was inset,
and the seed and arrangement of this photo's sampled look — see
[Variation](#variation).

Repeat per photo, or loop:

```bash
for f in /path/to/myproject/source/*; do
  stem=$(basename "${f%.*}")
  python compose.py --photo "$f" \
    --seal "/path/to/myproject/seals/${stem}_seal.png" \
    --caption "$stem" \
    --out "/path/to/myproject/output/${stem}.webp"
done
```

Defaults already produce the house format — 2048×2048 WebP at quality 92, the
correct band side, a straight seam, generous blank paper. You normally pass
nothing but `--photo`, `--seal`, `--caption`, and `--out`.

Each run also writes `IMG_1588.webp.json` beside the output, recording every
setting used:

```json
{
  "photo": "/tmp/demo/source/IMG_1588.heic",
  "out": "/tmp/demo/output/IMG_1588.webp",
  "seal": "/tmp/demo/seals/IMG_1588_seal.png",
  "caption": ["Teshima Art Museum", "Kagawa, Japan", "OCT 2019"],
  "canvas": 2048,
  "quality": 92,
  "anchor": "center",
  "seal_scale": 1.0,
  ...
}
```

That sidecar is what makes step 7 cheap.

### Step 5 — Gate the batch

```bash
python verify.py \
  --source-dir /path/to/myproject/source \
  --output-dir /path/to/myproject/output \
  --min-corr 0.985
```

```
PASS  96810F2D-F051-46BE-8F18-F6EE9B6DE53C.webp  2048x2048  portrait -> paper right  corr 1.0
PASS  IMG_1588.webp  2048x2048  landscape -> paper bottom  corr 0.9999

2/2 passed
```

Sources and outputs are matched by filename stem. Exit code is 0 when everything
passes and 1 when anything fails, so it drops straight into a script.

Use `--min-corr 0.985` for composites built by `compose.py` — they should be
near-exact. A failure here means something is wrong with the pipeline, not with
taste.

The canvas and orientation checks are absolute and never soften. Only the
fidelity test has a choice of metric, which matters if you ever take
[the other path](#the-other-path-letting-the-model-render-everything).

For comparison, this is the same gate run against outputs from the old
whole-frame workflow:

```
FAIL  96810F2D-F051-46BE-8F18-F6EE9B6DE53C.webp
        - not square: 2482x2048
        - not 2048x2048: 2482x2048
        - photo region does not match the source (correlation -0.309 < 0.9); likely cropped, distorted, or repainted
        - paper band is too dark (mean lightness 181.4); photo may have bled into it
```

### Step 6 — Look at them

The gate covers the mechanical half only. Open every output at full size and
judge the rest against
[`reference/checklist.md`](reference/checklist.md):
whether the seal reads as an ink impression rather than a shrunken photo, whether
its wear is irregular, whether the caption is spelled right, whether the paper
keeps its quiet.

Judge each seal **beside its photograph**, in the finished composite, never alone.
That pairing is what exposes the two failures easiest to accept by accident:

- **The competent poster.** Big flat colour fields, heavy slabs, thick outlines,
  three saturated inks. It looks strong on its own and drowns the photograph next
  to it. What you want instead is fine grain and stipple, broken edges, uneven
  pressure — small and quiet, closer to a botanical stamp than to a poster.
- **The same picture twice.** A seal so finely rendered, or so faithful to the
  whole frame, that the eye reads one image repeated rather than a photograph and
  its mark. Reseal with a focus: the primary subject, surroundings reduced to a
  stroke or dropped.

A third is simply a defect: a seal interior filled with repeated worm-like
squiggles, maze patterns, moiré, or fingerprint loops. Regenerate it — no flag
fixes it.

### Step 7 — Revise

Most revisions are a flag, so they cost nothing and cannot disturb the
photograph. Start from the sidecar `.webp.json`, change one value, rerun:

```bash
# smaller seal, moved into the bottom-left corner
python compose.py --photo .../IMG_1588.heic --seal .../IMG_1588_seal.png \
  --caption "Teshima Art Museum" --caption "Kagawa, Japan" --caption "OCT 2019" \
  --seal-scale 0.9 --anchor bottom-left \
  --out .../output/IMG_1588.webp
```

| You want | Flag |
|---|---|
| `缩小 10%` / smaller seal | `--seal-scale 0.9` |
| `移动到右下` / move the group | `--anchor bottom-right` |
| `纸张不要那么旧` / less aged paper | `--paper-tone 242,240,235 --mottle 1.6` |
| `纸张质地更细` / finer paper | `--grain 1.2` |
| caption too dark | `--caption-opacity 0.72` |
| seal ink too heavy | `--seal-strength 0.85` |
| caption under the seal, not beside it | `--layout stacked` |
| caption ink matching the seal colour | `--caption-tint 0.75` |
| caption letters too thin | `--caption-weight 0.3`. For a lighter caption lower `--caption-opacity`; do not thin the stroke |
| seal too clean, wants more press wear | `--seal-wear 0.8` |
| seal less clear on paper than the artwork was | `--seal-wear` should be `0`; on a seal with pale washes also try `--seal-knockout 8` |
| every seal equally half-legible | the press grade fluctuates per photo via `build_prompt.py --press` — check it was not pinned across the batch |
| caption too heavy | `--caption-opacity 0.72 --caption-weight 0` |
| caption too pale or patchy | `--caption-wear 0.1` for a fresh ribbon |
| caption too clean, wants more character | `--caption-wear 0.7` |
| a different look for this photo entirely | `--seed 41`, any number |

Only these need a fresh seal, because they are the artwork rather than the
layout: the shape, the focus (whole view vs. subject), the inks, the wear
character, and anything that reads as poster-like flatness.

Only a change to the seal *artwork* — shape, border, ink colour, wear character —
needs a new generation, and then you regenerate the seal alone and re-composite.
Never regenerate an accepted composite.

Full mapping, including the Chinese revision phrases, is in
[`reference/revisions.md`](reference/revisions.md).

## Using it with an agent

With the skill installed, the everyday prompt is one line. The conventions that
used to need spelling out every time — where the folders are, how rows are
counted, the caption format, the output naming — now live in `SKILL.md`, so the
agent already knows them.

**Everyday:**

```
用 colophon 处理 metadata.csv 第 112 到 121 行的图片。
```

```
Use colophon on rows 112-121 of manifest/metadata.csv.
```

That is enough. The skill supplies: sources from `source/`, seals into `seals/`,
results into `output/`; row numbers as data rows excluding the header; captions
as `place` / `city, country` / `MON year` read from the CSV by filename; output
basenames identical to their sources with only the extension changed to `.webp`;
2048×2048; no crop; no distortion; paper below for landscape and right for
portrait.

**When folders differ from the defaults:**

```
Use colophon on rows 112-121 of data/photos.csv.
Sources are in raw/, save results to build/stamps/.
```

**When you want something specific about the look:**

```
Use colophon on rows 112-121 of manifest/metadata.csv.
Prefer square-framed seals for the street scenes, let the sculpture seals focus
on the subject alone, and keep the paper very pale — less aged than usual.
```

**When you want the photo reinterpreted rather than preserved** — see
[the other path](#the-other-path-letting-the-model-render-everything):

```
Use colophon on rows 112-121, but render the whole frame as a
three-ink screen print rather than keeping the photograph. Gate with
--metric structural.
```

### What you should no longer need to type

Everything below is now in the skill. Saying it again is harmless but redundant:

- "保证印章美观，原图和印章部分都不要 distortion" — the photo is copied, not
  redrawn, so distortion is structurally impossible; `verify.py` proves it.
- "生成结果保存到 output 文件夹" — the default.
- "输出文件的 basename 必须与源文件保持一致，仅修改扩展名" — the default, and
  `plan_batch.py` derives it mechanically.
- The three caption lines and their example — the default caption format.
- "严格根据 skill.md 处理" — invoking the skill is what does this.

Worth keeping in your prompt: **which** photos, and anything you want that
differs from the house style.

### Checking the agent's work

Ask for the `verify.py` result if it is not offered. An agent that hands over
outputs without having run the gate has skipped the step that makes this
reliable. For a batch you can also confirm the selection yourself before it
starts:

```bash
cd scripts
python plan_batch.py --csv ../manifest/metadata.csv --rows 112-121 --check
```

```
OK      row  112  IMG_4705.heic
OK      row  113  IMG_4738.heic
...
10/10 sources present
```

The first and last filenames are the cheapest possible check that the row
numbers meant what you thought they meant.

## Variation

A batch where every caption sits in the same spot, in the same face, at the same
weight reads as a template. So `compose.py` samples a look for each photo —
within curated ranges that all stay inside the house style.

**What varies:** caption face, size, opacity, tracking, line spacing, stroke
weight, ink texture, per-glyph wobble, alignment, and whether the caption takes
the seal's own colour or stays neutral grey; the seal-and-caption layout and
where the group sits; seal scale and ink density; paper tone, grain, mottle,
margin, and gap.

**What never varies:** the canvas size, the orientation rule, the photograph.

The seed defaults to a checksum of the photo's filename, which gives you both
halves of what you want:

- every photo in a batch differs from its neighbours, with no effort;
- any one photo re-composites **identically** every time, so a revision changes
  only the thing you asked it to change.

Each run prints its seed and records it in the sidecar, so a look you like can be
pinned and reused:

```
output/IMG_1588.webp  2048x2048  landscape -> paper bottom  (bleed)  seed 194563074  stacked/right
```

| You want | Flag |
|---|---|
| a different look for this one photo | `--seed 41`, any number |
| more variety across the batch | `--variation 0.85` |
| less variety across the batch | `--variation 0.35` |
| every composite identical, as before | `--variation 0` |
| one property pinned, the rest sampled | pass that flag explicitly |

That last row is the important one. An explicit flag always beats the sampled
value, and only for the property you named — so `--caption-size 34` fixes the
size while the face, weight, tint, and placement keep varying. Reach for `--seed`
only when the whole arrangement is wrong; a reroll discards everything that was
already right.

Randomness in the *seal artwork* still comes from the image model, which is where
you want it. The script cannot invent a new seal; it varies everything around it.

## compose.py options

`--photo`, `--out`, `--seal`, and `--caption` are all you normally need.

### Fixed

| Option | Default | What it does |
|---|---|---|
| `--photo PATH` | required | Source photograph. jpg, png, heic, webp, tiff. |
| `--out PATH` | required | Output file. `.webp` or `.png` by extension. |
| `--seal PATH` | — | Seal artwork. Omit for a caption-only panel. |
| `--caption TEXT` | — | One line. Repeat the flag for more lines. |
| `--canvas N` | `2048` | Square output edge. |
| `--quality N` | `92` | WebP quality. |
| `--band-side SIDE` | `auto` | `auto` applies the house rule. `bottom` / `right` override it. |
| `--seal-knockout N` | `16` | How far below the seal's measured background the knockout ramp ends. |
| `--seal-raw` | off | Skip white-balance, knockout, and trim. For clean RGBA art. |
| `--caption-color R,G,B` | `86,82,76` | Neutral caption ink, before any tinting. |
| `--min-band F` | `0.16` | Smallest band before the photo is inset instead of bled. |
| `--max-band F` | `0.50` | Largest band. |
| `--no-manifest` | off | Skip the sidecar `.json`. |
| `--print-layout` | off | Print the resolved layout and exit without rendering. |

### Sampled

Each is drawn per photo unless you pass it explicitly.

| Option | Sampled range | What it does |
|---|---|---|
| `--variation F` | `0.65` | How far a sample may travel from the house default. `0` disables. |
| `--seed N` | filename checksum | This photo's look. Pass a number to reroll. |
| `--layout MODE` | split / stacked | Caption beside the seal, or under it. |
| `--anchor POS` | curated set | Where the group sits in the band. |
| `--seal-scale F` | `0.90`–`1.08` | Group size multiplier. |
| `--seal-strength F` | `0.88`–`1.00` | Seal ink density. |
| `--seal-wear F` | `0` (off) | Uneven pressure applied after the fact. Off by default — the prompt asks the model for it and places it better. Raise only to rescue a mechanically even seal. |
| `--caption-size N` | ±14% of canvas×0.0175 | Caption point size. |
| `--caption-wear F` | ~`0.11`–`0.74`, median `0.35` | Ribbon condition in one knob: 0 fresh (even, reasonably dark), 1 dry (pale, patchy, uneven letter to letter). Sets the four below together. |
| `--caption-opacity F` | from wear | Caption ink opacity. Pale by design, with a contrast floor so it stays readable. Overrides the ribbon. |
| `--caption-align SIDE` | left / center / right | Ragged edge, and which seal edge it hangs from. |
| `--caption-tracking F` | `0`–`2.6` | Extra pixels between glyphs. |
| `--caption-spacing F` | `1.46`–`1.82` | Line spacing multiple. |
| `--caption-weight F` | from wear | Stroke weight, in about one final pixel. Never negative: these faces are light already. Overrides the ribbon. |
| `--caption-texture F` | from wear | Mottled ink loss across the glyphs. Overrides the ribbon. |
| `--caption-jitter F` | `0`–`0.55` | Per-glyph baseline wobble, as a typed line sits unevenly. |
| `--caption-strike F` | from wear | Per-glyph variation in how hard the key landed. Overrides the ribbon. |
| `--caption-tint F` | `0` or `0.55`–`0.9` | How far the caption moves toward the seal's colour. |
| `--font PATH` | Courier New, Courier | Pins one face, overriding the sample. Bold Couriers are available here but not sampled. |
| `--paper-tone R,G,B` | around `237,235,229` | Paper base colour. |
| `--grain F` | `1.2`–`2.6` | Fine fibre amplitude. `0` disables. |
| `--mottle F` | `1.6`–`3.6` | Low-frequency tone variation. `0` disables. |
| `--paper-seed N` | random | Paper texture seed. |
| `--margin F` | `0.060`–`0.105` | Paper margin as a fraction of the canvas. |
| `--gap F` | ±30% of base | Gap between seal and caption. |

## Layout rules

**Which side the paper goes on** is derived from the source, not chosen:
landscape gets paper below, portrait gets paper on the right. Orientation is
measured after EXIF rotation is applied.

**Bleed vs inset.** Normally the photograph bleeds to the canvas edges and the
band takes whatever is left. Two cases cannot work that way without distorting or
cropping, so the photo is inset on the paper with margins instead:

- a near-square source, where a full-bleed photo would leave a sliver of paper;
- a very elongated source, where it would leave more paper than picture.

`inspect_source.py` says which case applies and why. Either way the photograph
keeps its true aspect ratio and its whole frame.

**Overriding the side.** `--band-side` exists for when you explicitly want the
other arrangement. Pass the same value to `verify.py`, or it will correctly report
the band as being on the wrong side. Overriding usually forces the inset layout,
because the band has to be carved out of the picture's own dimension.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `cannot identify image file '….heic'` | pillow-heif missing. `pip install pillow-heif`. |
| Pale rectangle around the seal | The seal's ground survived the knockout. Raise `--seal-knockout` to `24`. |
| Faint parts of the seal vanishing | Knockout too aggressive. Lower `--seal-knockout` to `8`. |
| `verify.py` says the band is on the wrong side | You passed `--band-side` to `compose.py` but not to `verify.py`. |
| `verify.py` fails on correlation, full-composite path | Lightly treated: `--min-corr 0.93`. Print or line art: `--metric structural`. See [the other path](#the-other-path-letting-the-model-render-everything). |
| Correlation is *negative* on a stylised output | Tone inverted by a print or line-art treatment. Use `--metric structural`, never a negative `--min-corr`. |
| Seal comes out tiny in the panel | Was a low-resolution seal: the fit only ever shrank, so small art stayed small. It now fills its panel regardless, and prints a note when that means a large enlargement — regenerate the seal bigger if it looks soft. |
| Seal is soft or blurry | The art was small and got enlarged to fill the panel. Check the run for the size note and regenerate the seal at a higher resolution. |
| Photo inset with margins, expected full bleed | The source is near-square or very elongated. See Layout rules. `inspect_source.py` reports the reason. |
| Caption in the wrong typeface | No Courier New on this machine. Pass `--font` explicitly. |
| Seal filled with squiggles, mazes, or loops | A failed seal. Regenerate it; no flag can fix it. |
| Seal looks like a bold poster or linocut | Large flat colour fields, heavy slabs, thick outlines. Reseal asking for "inked and pressed onto paper", fine grain and stipple, delicate not emphatic. Never say "cut coarse", "flat inks", or "carved block" — those phrasings cause it. |
| Seal reads as a filtered photograph | It was thresholded, halftoned, posterised, or traced rather than pressed. Reseal with the "NOT a processed photograph" clause; no flag can fix it. |
| Seal's colours look bolder or different from the photo | A stock palette was substituted. Run `check_seal.py`, then reseal with the `inspect_source.py` Palette line pasted into the prompt. |
| Seal is a shrunken copy of the whole frame | No focus was chosen. Reseal with the FOCUS paragraph, centring on the primary subject and reducing the surroundings to one stroke or dropping them. |
| Wrong photos processed from a CSV range | Row numbers are data rows, header excluded. Confirm with `plan_batch.py --check` before generating. |
| Caption tinted too pale to read | Already floored — the ink is darkened until what lands on the paper clears a minimum contrast, whatever the tint, opacity and paper tone. If it still reads faint for your taste, raise `--caption-opacity` or set `--caption-tint 0`. |
| Caption looks like a thin spindly serif | American Typewriter, which is proportionally spaced and finely drawn and does not survive this format's pale ink. The whole family is out of the pool; if you see it, `--font` was pinned to it. |
| Caption too thin | Raise `--caption-weight` toward `0.3`. Paleness should live in the ink colour, not the stroke. |
| Batch looks too samey, or too inconsistent | Raise or lower `--variation`. See [Variation](#variation). |
| Two runs of the same photo differ | They should not. Check whether `--seed` or a sampled flag was passed differently. |
| Caption face changes between photos | Working as intended — it is sampled. Pin it with `--font`, or use `--variation 0`. |

## The other path: letting the model render everything

Everything above describes the **default path**, where the model draws only the
seal and a script assembles the composite around an untouched photograph.

There is a second path, where the model renders the whole frame — photograph,
paper, seal, and caption — in one image. It is fully documented in
[`reference/full-composite-path.md`](reference/full-composite-path.md), and it is
not a lesser option. It is the right one whenever the photograph should be
**reinterpreted rather than preserved**.

### When you want it

- **The picture should become a print** — woodblock, risograph, screen print,
  engraving, line drawing. The scene redrawn in ink rather than photographed.
  `compose.py` cannot do this; it pastes a photograph, by design.
- **The photograph can't carry the frame** — too low-resolution, too compressed,
  motion-blurred, or damaged. A graphic treatment survives what a photograph
  won't.
- **You want one continuous printed surface** rather than the format's usual
  contrast between a photograph and a stamp.
- **Something should be abstracted away** — faces, plates, house numbers.

### When you don't

- The photograph matters as a document: people you want to recognise, signage you
  want to read, a place as it looked.
- You are only unhappy with the seal, caption, paper, or placement. Those are all
  flags on the default path — switching paths trades a guaranteed photograph for
  a change you could make in one line.

### What changes

| | Default path | Full-composite path |
|---|---|---|
| Photograph pixels | copied exactly | redrawn |
| Crop, framing, counts, signage | guaranteed | must be checked |
| Cost per image | one seal generation | one full generation |
| Revisions | free flag changes | mostly regeneration |
| Canvas size and band side | guaranteed | **still gated by verify.py** |

That last row is the point. Even here, `verify.py` enforces the square canvas and
the orientation rule absolutely — those checks never soften. Only the *fidelity*
test changes, because "faithful" means something different once the photograph
has been deliberately redrawn.

### Verifying a redrawn photograph

This is the part that will bite you if you skip it. A line-art treatment inverts
tone — the dark parts of the photograph become pale paper carrying dark ink — so
the default tone comparison scores it **negative**, worse than a completely wrong
image. Measured on two real sources:

| Treatment | `--metric tone` | `--metric structural` |
|---|---|---|
| identical | +1.000 | +1.000 |
| posterised | +0.97 | +0.95 |
| heavy print | +0.85 | +0.85 |
| **line art** | **−0.37 / −0.74** | **+0.70 / +0.79** |
| cropped to 80% | — | +0.12 / +0.24 |
| wrong image | +0.01 / +0.22 | −0.05 / +0.31 |

So gate a stylised batch on tone and you reject all of it. `--metric structural`
compares edge structure instead, ignoring tone and polarity — it still catches a
crop (0.12–0.24) and a wrong image (−0.05 to 0.31) well below its 0.55 threshold.

```bash
python verify.py --source-dir source --output-dir output --metric structural
```

`verify.py` recognises this exact case and says so rather than leaving you to
guess:

```
FAIL  a.png
        - photo region does not match the source by tone (correlation -0.362 < 0.9),
          but its structure does (structural 0.715). This is what a print or line-art
          treatment looks like: same scene, inverted tone. If that was intended,
          re-run with --metric structural.
```

Do not answer that by lowering `--min-corr` toward zero — a negative threshold
accepts anything. Switch the metric.

### One thing the default path simply does better

The caption. On the full-composite path the model renders the text, so it can
misspell it, and place names and dates are exactly what models approximate. On
the default path the caption is real text drawn at full resolution. If captions
keep coming back wrong, generate the frame without one and composite the text
separately.
